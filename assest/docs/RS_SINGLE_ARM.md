# B601-RS 单臂 MIT 遥操

本文介绍 RS 单臂 MIT；RS 双臂使用同一控制流程，见 [RS 双臂说明](RS_DUAL_ARM.md)。
现有 DM 单／双臂保持兼容。不包含 RS POS_VEL 或训练数据采集。

## 硬件与模型

- SocketCAN 通道默认 `can0`，本机 USB-CAN 已确认使用 `peak_usb`，接口已启用，波特率 1 Mbps。
- 电机 ID 1–3：`rs-06`；4–7：`rs-00`；主机／反馈 ID `0xFD`。
- 软件边界使用 LeRobot 风格的度数 `.pos`；IK、动力学、MotorBridge 原生命令使用 rad、rad/s、N·m。
- RS 使用原生 URDF 坐标，q2/q3 为正向工作区；不套用 DM 的初始姿态符号转换。
- 启动和运行反馈检查允许关节边界外 0.1° 的微小读数误差，避免校零后的量化／抖动触发误报；
  实际反馈照常保留，控制姿态和运动目标仍限制在原始关节范围内。超过该反馈容差仍拒绝启动或进入故障保持。
- 模型来源：[Seeed-Projects/reBotArm_control_py](https://github.com/Seeed-Projects/reBotArm_control_py/blob/6415d43130d1e143c70dc106096a857ac5556f81/urdf/RS/urdf/ReBot_Arm_RS.urdf)。
  内置 `rebot_b601_rs.urdf` 删除渲染／碰撞网格，将两个夹指滑动关节固定在零位，保留六轴几何与全部惯性。
  固定夹指模型提供重力补偿近似，不表示已测量夹爪电机角度到夹指位移的映射。
- 依赖 MotorBridge >=0.5.3,<1；不依赖上游完整 Python 包（其 Python 版本要求与本工程不同）。

## 只读反馈检查

```bash
source /home/verser/Python/lerobot/.venv/bin/activate
PYTHONPATH=src python -m lerobot_teleoperator_rebot_vr.tools.rs_probe --port can0 --samples 3
```

工具只读 `mechPos (0x7019)`，不会使能、失能、设置零位、切换模式或发送运动命令。
默认保存 `logs/rs_probe/<时间戳>.jsonl`，含每关节读数和请求起止时间。缺失回复会输出错误并以非零状态退出。

零位未知时只能做此检查。接近 0 的反馈不证明机械零位正确；需要实体姿态、关节方向与零位定义共同核对。
该工具也不能仅凭一个闭合位置推断全开位置或夹爪行程。

## 遥操前提与命令

### 标准校准命令

在本工程已安装的 LeRobot 环境中，使用统一入口：

```bash
lerobot-calibrate \
  --robot.type=rebot_b601_rs_follower \
  --robot.port=can0 \
  --robot.id=rebot_b601_rs_vr
```

该类型由本工程插件注册，无需修改 LeRobot 源码。若类型列表没有 RS，先在当前环境从工程根目录
运行 `python -m pip install -e .`。校准入口仅打开通信，不自动使能、切换模式或发送运动指令。
当前注册适配器用于标准校准和反馈；运动下发由本工程的 VR MIT 路径负责，不是完整的 LeRobot 录制／策略运行适配器。

先退出遥操、MotorBridge Gateway 等使用这组电机的程序。参考
[官方 RS 快速入门的校零演示](https://wiki.seeedstudio.com/cn/rebot_b601_rs_getting_started/)
将实体六轴摆到官方零位并可靠支撑，将夹爪完全闭合，看到 `Press ENTER when ready...` 后按回车。
本次把 ID 1–7 的当前位置定义为零点。不能把任意姿态设为本模型零位；软件不能验证实体是否摆对。
英文提示与 DM 一致。已有有效记录时，回车保留；输入 `c` 后，在摆好零位的提示处按回车才重新校零。
如需保留夹爪当前零点，可加 `--robot.calibrate_gripper=false`，仅校六轴。

成功后按 `robot.id` 保存到 LeRobot 的标定目录，默认路径为：

```text
~/.cache/huggingface/lerobot/calibration/robots/rebot_b601_rs_follower/rebot_b601_rs_vr.json
```

路径会随 `HF_HOME`／LeRobot 缓存设置变化，以终端显示为准。
RS 使用插件自己的记录格式，含机器人 ID、模型指纹、电机 ID／型号、校零轴、回读结果与完成状态；
不虚构夹爪行程。日志保存在同一目录的 `<robot.id>_<时间戳>.jsonl`。
重新写零前旧记录会标为无效；中途失败或中断后不会把旧标定继续当作有效。已经写零的电机不会自动回滚。
记录中的旧数据供排查使用，不是能还原电机参数的完整备份。

工具先向七轴发送失能命令，检查支撑前后位置变化，再逐轴写零并回读。
0.5° 是移动检测／回读阈值，不表示实体摆放精度；RS 故障码不能证明使能状态，需停止其他控制进程并保持支撑。
完成后不会自动使能。重新上电后仍应通过 `tools.rs_probe` 核对零点是否保留，并核对实体姿态和关节正方向。
如果七号电机重新置零，之前观测的 −11.03° 闭合角度失效；全开端点需重新测量。

旧的 `tools.rs_zero --execute` 仍可使用，现在也会按 `--robot-id` 保存同一格式的记录，
但默认仍仅校六轴，加入 `--include-gripper` 才校七轴。不带 `--execute` 仍是只读检查。

### 启动遥操

校零完成后，用相同的机器人 ID 启动：

```bash
rebot-vr-teleoperate \
  --robot-model b601_rs \
  --robot-port can0 \
  --robot-id rebot_b601_rs_vr \
  --motor-control-mode mit \
  --control-config config/rs_mit_split.yaml
```

VR 自动读取该 ID 的标定记录，无需再加 `--rs-zero-confirmed`。
缺失、未完成、身份或模型不匹配的记录会在打开 VR／CAN 前被拒绝。
自定义标定目录时，校准使用 `--robot.calibration_dir=/path`，遥操使用 `--calibration-dir /path`。
历史参数 `--rs-zero-confirmed` 保留为人工确认入口；正常流程使用标定记录，不需要它。
记录只证明对应 ID 的校零流程成功，不会验证当前接线是否换成了另一台机械臂。

默认载入 `config/rs_mit_split.yaml`：50 Hz，臂／腕限速 1.0 rad/s，加速度 2.0 rad/s²，
六轴命令与反馈最大偏差 3°，位移／姿态缩放 1.0。退出回零使用 0.5 rad/s、1.0 rad/s²。
启动自动移动到 `[0, 0.8, 0.8, 0, 0, 0]` rad，
无需按 Grip；到位后进入 VR 遥操。正常运行时第一次 Ctrl+C 先让六轴回零、再退出，夹爪保持。
RS 默认 `disable_torque_on_disconnect: true`，正常 Ctrl+C 回零验证成功后自动失能；退出前需可靠支撑。
不发送失能命令不等于硬件永久保持保证：电机通信超时、供电和故障策略仍可能卸力。
再次 Ctrl+C 中止回零并保留力矩。启动失败、反馈故障、程序异常或定时结束不自动回零；
RS 未验证退出回零完成时，即使配置要求失能，也会阻止自动失能。
临时关闭对应行为可分别传入 `--no-move-to-initial` 和 `--no-return-to-zero-on-exit`。

### 回零残差与退出保护

`rs_gripper_check_v2.csv` 曾在肘关节仍差 2.63° 时记录回零完成：旧到位阈值为 3°，
随后立即失能导致未落稳的机械臂下坠。现 RS 退出阈值收紧为 0.5°，
六轴反馈必须连续稳定至少 0.5 秒、估算速度不超过 1°/s，且目标指令已到零点附近。
回零失败或中断会保留力矩，不再失败后仍直接失能。
RS 退出回零逐轴检查最近 5 秒：相对窗口内该轴的最大误差，改善达到位阈值的 5%
（默认 0.025°）即算有进展。已进入容差的轴清除自己的停滞窗口。
不再与全程历史最低的“最大关节误差”比较，避免最大误差轴切换、耦合短暂超调后的
恢复被误判为停滞。固定超差、持续恶化仍会失败，总超时仍为 30 秒。
终端误差显示四位小数，停滞异常列出超差关节和准确误差，避免 0.504° 显示成 0.5° 造成误解。

手柄 B/Y 回零遇到 Tracking 丢失时暂停，恢复有效 Tracking 且 Grip 松开后继续原目标；
重新按 Grip 进入跟随或反馈故障会取消回位。终端显示回位目标和当前最大误差。

RS 在零点附近增加缓慢的前馈误差补偿：只有明确回零、对应轴目标在 0.05° 内、
实际角度在 5° 内且反馈速度不超过 5°/s 时才积分；0.1° 内不再积累。
积分增益 10 N·m/(rad·s)，变化率最多 0.5 N·m/s，幅值上限为配置前馈限幅的 25%，
并进一步限制前三轴各 2 N·m、后三轴各 0.75 N·m。最终前馈仍经过原有限幅。
离开回零或丢失 Tracking 后补偿缓慢退出，反馈异常 HOLD 保留最后一次有效指令。
回零附近的关节突破静摩擦、速度超过积分门限时，仅冻结已有补偿，不再立即撤回补偿。
该补偿只对 RS 生效，不增加关节位置范围，也不代表已检测到桌面接触。
CSV 的 `zero_trim_<joint>_nm` 记录补偿，`mit_feedforward_<joint>_nm` 是最终前馈。
此修正通过离线仿真与故障路径测试，实机精度和电机断开通信后的保持行为仍需确认。
配置中的 MIT 增益和前馈限值是待实机验证的实验起点，尚未完成带载遥操调参；前馈限值不是总电机输出力矩限值。

六轴 MIT 增益参考
[Seeed 官方 LeRobot RS 配置](https://github.com/Seeed-Projects/lerobot-robot-seeed-b601/blob/0da1a1a5575905d77823227003ffee7672059780/lerobot_robot_seeed_b601/config_seeed_b601_rs_follower.py)
的 `gravity_mit_kp`／`gravity_mit_kd`，顺序为 q1–q6：

```yaml
mit_kp: [50, 50, 50, 30, 50, 50]
mit_kd: [3, 5, 5, 3, 4, 4]
```

上游另有不带重力补偿的参数组（Kp `[50,150,150,50,50,50]`，Kd `[3,10,10,5,4,4]`），
其默认关闭重力补偿；本工程 `mit_gravity_scale: 1.0`，因此使用其重力补偿参数组。
这些增益直接作用于电机原生弧度坐标，上游的关节方向／限位映射不随增益复制。
本工程仍使用自己的 URDF、Pinocchio 重力计算、前馈限幅和 QP 速度目标；上游六轴 MIT 的速度目标为零，
所以相同增益不代表动态响应已经实机验证。

上游夹爪的 Kp=12、Kd=0.05 用于软件阻抗计算与力矩限幅，最终下发的是
`send_mit(0, 0, 0, 1.5, tau_ff)`。本工程夹爪使用电机端位置 PD 保持，继续采用 Kp=5、Kd=0.3，
不能只复制那两个软件增益来替代完整的夹爪控制逻辑。

Grip 按住跟随，松开保持；跟踪恢复后必须先松开。A/X 回配置初始位、B/Y 回六轴零位仍然有效，
不受自动启动／退出移动开关影响。首次验证期间不要按回位键。
默认退出会断使能；若反馈严重异常，沿用现有故障保持／保留力矩策略。详情见 README 的退出说明。

## 夹爪

RS 默认 `gripper_enabled: true`，全开 `gripper_open_deg: 310.12`，闭合 `gripper_closed_deg: 0.0`。
闭合端点来自完全闭合后的电机校零。2026-10-10 用户确认完全打开时的三次读数为
310.131°、310.122°、310.118°，见 `logs/rs_probe/20261010_100311_175854.jsonl`。
端点绑定这台机械臂及其当前零位；校零前的 −11.03° 闭合读数已失效。

新鲜 Tracking 中 Trigger 独立于 Grip 生效：松开对应全开，按到底对应闭合，中间位置线性插值。
当前夹爪配置限速 300°/s、加速度 1200°/s²（电机轴角度单位）。
完整行程在理想跟随、从静止加速并减速停止的条件下约 1.28 秒，实际还取决于跟随情况；
这不是已验证的机械最大速度。扳机按到底才请求全闭合，轻扣仍按比例控制开度。
初次收到有效 Tracking 且 Trigger 松开时，夹爪会向全开移动。
可用 `--no-gripper-enabled` 临时恢复当前位置保持；此时 Trigger、回位按键不改变夹爪目标。

### 开合和回位平滑性

RS 夹爪被反馈误差窗口裁剪后保留实际指令变化速度，避免每次裁剪清零速度造成反复加速。
RS 夹爪、启动以及手柄/退出回位轨迹按剩余距离提前减速；跟随误差和关节硬限位仍优先。
DM 的轨迹选项保持原样。RS 夹爪保持 Kp=5、Kd=0.3 和 12° 反馈误差窗口。

`rs_zero_check_v3.csv` 中退出循环间隔中位数约 20.09 ms，99 分位约 21.14 ms；
读取和调度暂未显示明显阻塞。接近零点时肘关节曾突破静摩擦快速移动，同时补偿被速度门限触发撤回，
现改为冻结补偿。机械摩擦、模型误差和 MIT 零速度目标产生的阻尼仍可能影响跟随。
六轴启动/回位的 MIT 速度目标仍为零。

`logs/rs_smooth_check.csv` 中一次完整闭合约 3.4 秒，运动段约 110°/s；
当时限速 120°/s、加速度 240°/s²，夹爪速度目标仍为零。
按 MIT 的 `Kp*(q_des-q) + Kd*(v_des-v)` 关系，速度目标为零时，
120°/s 下的阻尼项约为 -0.628 N·m，抵消部分位置驱动力。
现在 RS 夹爪将经限速、限加速度、提前减速及反馈窗口处理的轨迹速度一起下发，
运动中阻尼跟踪目标速度。反馈窗口因遇阻固定后，轨迹速度降为零，不持续追加速度驱动力。
位置误差项仍最多约 0.942 N·m；加入速度目标会改变运动期间的力矩，不能把该数值当总力矩限制。
速度指令只对当次动作生效；丢失 Tracking、反馈 HOLD、禁用夹爪和退出回零时均为零。
`logs/rs_gripper_fast.csv` 已验证 240°/s、960°/s² 配合速度目标时，运动段实际速度约 240°/s。
从全闭合目标发出到反馈进入闭合点 ±3°，两次接近全行程闭合分别用时 1.309、1.411 秒；
同口径旧日志为 3.186 秒。该次测试闭合侧最大超调约 1.67°（电机角度）。
为进一步提速，当前配置将速度、加速度各提高 25%；保留到位减速、反馈误差限制及 Kp/Kd。
300°/s、1200°/s² 尚需实机验证，可用 `--csv-log logs/rs_gripper_300.csv --status-rate 1` 记录。
CSV 新增 `mit_desired_velocity_gripper_deg_s`，用于核对实际发送的速度目标。

### Trigger 无响应时的诊断

默认选择右手手柄，夹爪使用食指 Trigger，独立于侧面的 Grip。
在原启动命令后加入以下参数，将诊断写入文件并降低终端刷新频率：

```bash
--csv-log logs/rs_gripper_check.csv --status-rate 1
```

保持 Grip 松开，缓慢按下、松开右手 Trigger，各保持约 3 秒，重复两次后正常退出。
该操作沿用配置中的自动起始姿态及 Ctrl+C 六轴回零行为；新一轮诊断请使用不同文件名，避免覆盖。
CSV 包含 `trigger`、`tracking`、`feedback_valid`、`gripper_trigger_active`、
`target_gripper_deg`、`command_gripper_deg`、`sent_gripper_deg`、`actual_gripper_deg`。
`gripper_command_sent` 仅表示发送接口成功返回，不代表电机确认执行。
实际加载的参数保存在同名 `_config.json` 文件中。

2026-10-10 的 `logs/rs_gripper_check.csv` 确认 Trigger 在 0～1 变化、目标在 0～310.12° 变化，
但夹爪反馈范围仅 -0.0857～0.0022°；连续 5.43 秒开爪时指令与反馈之差饱和在 2.7°。
原 `gripper_relative_target_deg: null` 继承机械臂 3° 限制，控制器采用其中 90%，
故 Kp=5 的位置误差力矩项最多约 0.236 N·m。
现在为 RS 夹爪独立设置 `gripper_relative_target_deg: 12.0`，控制器窗口为 10.8°，
位置误差力矩项最多约 0.942 N·m；电机指令分发层仍有独立的 12° 限制。
保留 Kp=5、Kd=0.3；后续速度调整及其验证依据见上文“开合和回位平滑性”。
日志未直接测量电机输出力矩，不能完全排除使能/模式或机械问题。
`estimated_position_effort_gripper_nm` 仅记录该位置误差项，不是实测力矩或总力矩上限。
若 Trigger 和下发目标均变化而反馈基本不动，需进一步排查驱动力、模式/使能和机械阻力；
仅凭全开角度读数不能确认电机运动控制正常。
两种角度方向都支持，但启用时缺失或相同端点会被拒绝。更换机械臂或改变零位后需重新测量。

## 反馈和清理契约

- 逐电机调用明确主机 ID 的参数读取接口，避免 SDK 自动探测其他主机 ID 的长重试。
- 七个独立读取请求通过固定七线程池并行等待；每电机同一时刻只有一个请求。
  等所有请求返回后才做 IK 或下发，退出时先结束读取线程再释放硬件句柄。
- SDK 的等待轮询间隔约 8 ms；批量等待避免逐轴累计约 57 ms。初始三次实测批量耗时为 9.74、9.64、9.39 ms。
- 参数读取无回复、非有限数、已观察到的故障标志或整组读取跨度超过 100 ms，均报告反馈故障。
  不把旧状态缓存、读取失败或缺失字段伪装成零角度。
- 请求／完成时间是主机软件测量，不是电机采样硬件时间戳；SDK 协议本身没有请求序列号。
  不允许另一个控制／诊断程序同时操作这组电机，尤其不能并发读写同一参数。
- RS 原始速度反馈语义尚未验证，CSV 中相应速度、力矩及 PD 力矩估计字段留空。
- MotorBridge 的 RS `status_code` 是故障位，不是 DM 的使能状态码；执行失能时重试，但不把零故障码当作失能确认。
- 所有运动发送异常向上传播；半途连接失败也走统一清理，不忽略某一个电机的失败。
