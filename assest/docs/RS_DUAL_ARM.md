# B601-RS 双臂 MIT 遥操

使用现有 `rebot-vr-teleoperate-dual` 入口，配置为 `config/dual_rs_mit_split.yaml`。
两臂共用一个 VR 接收服务，左右臂各自使用独立 CAN、反馈线程、IK、轨迹状态和日志。
沿用 DM 双臂的操作及故障联动，不把 DM 的电机参数或 q2/q3 符号转换套到 RS。

## 当前接线和标定

2026-10-10 用户确认如下对应关系；系统检查两路均已 UP、1 Mbps、ERROR-ACTIVE，错误计数为 0。
接口状态不等于七个电机通信均已验证。后续用户已分别完成 left/right 标定；
标定写入及回读接近零不等于实体零位、重力模型和带力矩回零均已验证。

| 对应臂 | 手柄 | CAN | 标定 ID | 夹爪 |
| --- | --- | --- | --- | --- |
| 左 | 左手 | can0 | rebot_b601_rs_left | 闭合 0°、全开参考值 310.12°，重标定后核对 |
| 右 | 右手 | can1 | rebot_b601_rs_right | 按用户要求采用左侧端点：闭合 0°、全开 310.12° |

两条独立总线均可使用电机 ID 1～7，主机 ID 0xFD，不需要为了双臂改电机 ID。
CAN 名称可能随 USB 重插或重启变化；启动前核对实体左右臂与接口。
默认要求两臂竖直安装、同向并排；没有跨臂碰撞检测或共同物体约束。

退出其他电机程序，按官方 RS 零位姿态摆好待标定臂的六轴并可靠支撑，完全闭合其夹爪。
左右臂分别执行，先完成左臂，再完成右臂：

```bash
# 左臂
lerobot-calibrate \
  --robot.type=rebot_b601_rs_follower \
  --robot.port=can0 \
  --robot.id=rebot_b601_rs_left

# 右臂
lerobot-calibrate \
  --robot.type=rebot_b601_rs_follower \
  --robot.port=can1 \
  --robot.id=rebot_b601_rs_right
```

看到 `Press ENTER when ready...` 后按回车。校零写入并回读七个电机零位，保存独立记录，不自动使能。
仅夹爪闭合不能说明六轴已处于官方零位；不要复制左臂标定记录给右臂。
双臂使用新的 left/right ID，不再读取原单臂 ID `rebot_b601_rs_vr` 的记录。
原文件无需删除；重标定后核对两侧实体零位及夹爪行程，左夹爪 310.12° 是此前的参考值。
双臂入口在打开 VR、启动任何 CAN 工作线程前检查两侧 RS 标定；单臂连接时再次检查。
`--dry-run` 只检查参数，不检验标定文件、硬件连通性或实体零点；`no_calibrate` 不能绕过 RS 零位检查。

## 右夹爪行程

按用户要求，`arms.right.overrides.robot.gripper_enabled` 当前为 `true`。
左右夹爪共用 `rs_mit_split.yaml` 的配置：闭合 0°、全开 310.12°，
MIT Kp=5.0、Kd=0.3，最大速度 300°/s、加速度 1200°/s²，相对目标限制 12°。
右 Trigger 控制开合，右 B 键回零时闭合夹爪。
右侧端点为用户指定沿用左侧的值，尚不是右夹爪独立实测结果。

右臂校零后，在退出控制程序、机械臂可靠支撑且电机失能时，将右夹爪轻轻置于全开位置；
如不能手动移动，不要强行扳动。读取全开角度：

```bash
PYTHONPATH=src python -m lerobot_teleoperator_rebot_vr.tools.rs_probe \
  --port can1 --samples 3
```

该工具只读位置，不使能、不改模式、不校零、不发送运动指令。
如后续实测行程不同，可在双臂 YAML 的右侧 `overrides.gripper` 中覆盖
`gripper_open_deg` 和 `gripper_closed_deg`。左右臂也可在各自 `overrides`
内独立设置夹爪速度、加速度和行程。

## 启动

```bash
# 仅验证并打印参数，不连接 VR 或 CAN
rebot-vr-teleoperate-dual --config config/dual_rs_mit_split.yaml --dry-run

# 标定与实体姿态确认后：实机低速启动/回零检查，无 VR 控制
rebot-vr-teleoperate-dual --config config/dual_rs_mit_split.yaml --startup-zero-test

# 正常双臂遥操
rebot-vr-teleoperate-dual --config config/dual_rs_mit_split.yaml
```

低速检查将臂/腕速度限制到 0.25 rad/s、加速度限制到 0.5 rad/s²；
两侧到达初始姿态后保持 2 秒，再请求回零。它会实际使能和移动机械臂。
正常配置自动移动到 RS 原生坐标 `[0, 0.8, 0.8, 0, 0, 0]` rad，然后允许 VR 操作。
当前位置/姿态映射比例左侧为 1.0/1.0，右侧为 0.5/0.6。
两侧大臂和手腕速度上限均为 1.5 rad/s，加速度上限均为 3.0 rad/s²，
为用户要求的提速调试值；MIT 参数及夹爪配置共用 RS 单臂配置。

## 手柄和退出

当前双臂配置按用户要求，将两侧 `startup.exit_zero_tolerance_deg` 设为 **2.0°**。
六轴均在此容差内并满足原有稳定条件后，执行退出失能策略。
这改变到位判据，不会消除实际角度误差；下文实测记录中的 0.5° 为当时使用的判据。

| 操作 | 行为 |
| --- | --- |
| 左/右 Grip | 按住对应臂跟随，松开保持；启动和恢复后先完全松开再按 |
| 左/右 Trigger | 独立控制对应夹爪，不依赖 Grip |
| 左 X / 右 A | 对应臂返回初始姿态 |
| 左 Y / 右 B | 对应臂返回六轴零位，已启用的夹爪闭合 |
| 第一次 Ctrl+C | 健康运行时两臂按各自配置回零后退出 |
| 第二次 Ctrl+C / SIGTERM | 中断回零并清理，RS 未验证回零时保留力矩 |

任一手柄跟踪丢失或任一臂反馈无效，双方停止跟随；恢复后需释放 Grip 再激活。
持续反馈故障、连接/启动失败会终止整个会话，不自动回零。
两臂分别验证实际反馈回零、稳定到位，成功的一侧按配置失能；回零失败/中断的一侧不自动失能，
并中止另一侧尚在进行的回零。已先完成退出的一侧不会因另一侧后续失败而重新使能。
退出前可靠支撑两臂；保留力矩不能保证通信超时或断电后仍保持。
RS SDK 仅提供故障位，日志中的 `confirmed=NO` 不能确认实际失能状态。

### 右臂回零等待

`logs/dual_rs/be6defb846e9/` 的实机记录中，右腕约 0.76° 的误差触发 5 秒停滞检查，
当时右肘仍约 2.08°；两臂均未发送失能，左臂回零被联动中止。
右腕回零补偿仍在增加，终止时约 -0.652 N·m，尚未到原有 -0.75 N·m 上限。
用户确认两臂同向竖直安装、空载且无接触。日志不足以区分摩擦、负载/模型差异等物理原因。

右臂 `overrides.startup.exit_zero_stall_timeout: 10.0` 单独延长退出回零的无进展等待，
给现有缓慢补偿更多收敛时间。启动仍使用 `initial_stall_timeout: 5.0`，左臂仍沿用原设置。
不提高补偿上限或增益；到位要求仍为 0.5° 并稳定保持，总超时仍为 30 秒。
后续实测 `logs/dual_rs/345932e8a440/` 表明延长等待仍未解决右臂残差：

| 项目 | 左臂 | 右臂 |
| --- | --- | --- |
| 回零结果 | 7.69 秒后通过，最大误差 0.437° | 13.50 秒后停滞失败 |
| 最后肘/腕误差 | 0.437° / 0.431° | 1.970° / 0.727° |
| 退出动作 | 七个电机各发送三次失能 | 未发送失能，保持保留力矩策略 |

右肘补偿约在第 9 秒达到 -2.0 N·m 上限，右腕随后达到 -0.75 N·m 上限，
结束前仍未收敛。两侧控制周期中位数约 20.1 ms，99 分位小于 22 ms，
现有时序记录未显示明显阻塞。不能再把该结果仅归因于等待时间不足。
程序中的型号映射及 Kp/Kd 与参考配置一致，但日志没有可靠的实测输出力矩/电流，
不足以区分实体电机参数差异、摩擦和重力模型误差。下一步应针对右肘/右腕核查这些因素，
不应把扩大到位容差当作已经回零。
CLI 对应 `--exit-zero-stall-timeout`；缺省为 `null`，沿用 `initial_stall_timeout`。

### 右臂残差的只读排查（2026-10-10）

`logs/dual_rs/72e7f7d496c9/` 再次复现：左臂约 10.36 秒到位，
最大误差 0.491°，随后发送失能；右臂约 12.45 秒失败，肘/腕误差为
1.887° / 0.870°，补偿分别达到 -2.0 / -0.75 N·m 上限，未发送失能。
这不是日志四舍五入造成的 0.5° 边界问题。

退出遥操后可读取电机参数快照：

```bash
PYTHONPATH=src python -m lerobot_teleoperator_rebot_vr.tools.rs_diagnostics \
  --ports can0 can1 --samples 3
```

工具只调用参数读取和 CAN 连接关闭，不使能、不失能、不改模式、零位或目标。
默认读取两侧肘和腕；`--joints` 可指定其他关节。读取错误单独记录并返回非零退出码，
不会把读取失败伪装为零电流。应在遥操退出后运行，避免并发参数请求干扰反馈。

实际记录：`logs/rs_diagnostics/20261010_150143_900672.jsonl`，所有参数读取成功。

| 关节 | 左臂角度 / Iq | 右臂角度 / Iq | 左右相同的读取值 |
| --- | --- | --- | --- |
| elbow_flex | 0.012～0.017° / 0 A | 1.621～1.631° / 4.814～4.884 A | 原生模式 0（MIT）、力矩限制 36 N·m |
| wrist_flex | 0.046～0.051° / 0 A | 0.857～0.864° / 0.744～0.750 A | 原生模式 0（MIT）、力矩限制 14 N·m |

对应关节读取的电流环增益、滤波系数、位置/速度环增益及限制均一致；
供电为 47.48～48.44 V，未显示明显供电电压下降。
右臂退出后仍有驱动电流，与保留力矩策略一致；左侧零电流与已发送失能一致。
原生模式 0 仅表示 MIT 模式，不能作为使能/失能状态位。
位置/速度模式参数不一定作用于 MIT 控制，不能用它们替代 MIT 帧中的 Kp/Kd。

这些是退出后的逐项读取，不能当作此前回零时的同步电流记录，Iq 也不是已标定的输出力矩。
目前可确认静态跟踪残差和补偿饱和；尚不能区分重力前馈偏大、实际电机力矩换算、
实体零位/质量参数及摩擦等原因。下一步应在可靠支撑与现场观察下，单独对右肘/右腕做
有界的近零位前馈对比，记录位置、电流及运动方向，再决定是否调整该臂的补偿。
直接关闭整臂重力补偿或提高补偿上限需要进一步验证；放宽到位判据不代表实际残差已消除。

## 日志与验证范围

默认保存到 `logs/dual_rs/<运行ID>/`，左右各自包含 CSV、参数快照、时延汇总和退出报告。
复用双臂会话、真实 RS 运行路径及假 CAN 做离线测试，覆盖左右命令隔离、夹爪速度目标、
RS 启动坐标、标定预检查、连接失败、反馈故障、正常/中断/失败回零和资源关闭。
上述测试不替代两条实体机械臂的零位、方向、运动和夹爪行程验证。
